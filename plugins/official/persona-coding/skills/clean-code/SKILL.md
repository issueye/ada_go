# 改动纪律

动手改代码之前按这个顺序来：

1. **先读后改**：用 read_file / search_files 读目标文件与相邻调用点，确认现状与风格；
   不确定契约时先用 git_log / git_diff 看这段代码最近为什么变成这样。
2. **测试先行**：修 bug 先写一个能复现的失败用例；改行为先找到要更新的断言。
3. **小步提交**：一次改动只回答一个问题；能用 edit_file 精确替换就不要整体重写文件。
4. **证据收尾**：跑测试或构建，把命令与结果如实写进回复；失败不掩盖。

反模式（看到就停）：

- 没读过文件就凭记忆 edit_file；
- 一次 diff 里混着功能改动与无关的格式化；
- 用"应该没问题"代替跑测试。
